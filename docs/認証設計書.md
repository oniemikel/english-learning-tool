# 1. 目的

本書では、要件定義書および基本設計書に基づき、初期フェーズの認証・セッション・認可仕様を定義する。

# 2. 採用方式

## 2.1 認証方式

- 認証プロバイダーはGoogle OAuth 2.0のみとする。
- Next.js上ではAuth.jsを利用する。
- メールアドレス・パスワードによるログインは初期フェーズでは提供しない。
- パスワードおよびパスワードハッシュは保存しない。
- 新規ユーザーはGoogle認証成功時に作成する。
- 既存ユーザーはGoogleのプロバイダー識別子を優先して特定し、未登録時のみメールアドレスを補助的に使用する。

## 2.2 セッション方式

- Auth.jsのJWTセッション方式を採用する。
- サーバー側にセッション本文、アクセストークン、リフレッシュトークンを永続保存しない。
- セッションCookieはAuth.jsが管理する一時的なHttpOnly Cookieとする。
- Cookieは本番環境で`Secure`、`HttpOnly`、`SameSite=Lax`を有効にする。
- セッション有効期間は7日とし、利用中はAuth.jsの標準更新処理に従う。
- JWTにはユーザー識別子、認証プロバイダー、セッション有効期限のみを保持する。
- GoogleのアクセストークンおよびリフレッシュトークンをJWTへ格納しない。

## 2.3 OAuth保護

- OAuthのstate、PKCE、nonce検証はAuth.jsの標準機構を利用する。
- OAuth callback URLは許可した環境のURLのみ受け付ける。
- `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`AUTH_SECRET`はサーバー専用環境変数とする。
- 認証情報をログ、IndexedDB、localStorageへ出力・保存しない。

# 3. Userデータ設計

現行の詳細設計書およびPrisma Schemaにある必須`passwordHash`は、要件定義書の「パスワードは保存しない」と矛盾するため、初期認証方式の確定に伴い削除する。

UserにはGoogleアカウントを一意に識別するため、以下の項目を追加する。

| 項目 | 型 | 制約 | 説明 |
| --- | --- | --- | --- |
| authProvider | Enum | 必須 | 初期値は`GOOGLE` |
| providerAccountId | String | UNIQUE | Googleのsub値 |

`email`は表示・連絡先および補助検索用として保持する。Google側でメールアドレスが変更されても、`providerAccountId`を主識別子として同一ユーザーを特定する。

## 3.1 Enum

```prisma
enum AuthProvider {
    GOOGLE
}
```

## 3.2 論理削除ユーザー

- `deletedAt`が設定されたユーザーは認証成功扱いにしない。
- 認証済みセッションが存在していても、各保護APIでUserの有効性を再確認する。
- 論理削除ユーザーのセッションは認証コールバックで無効化する。

# 4. 認可

## 4.1 認証不要

- ログイン画面
- OAuth開始・callback処理
- `GET /api/health`
- 公開デッキ閲覧（公開デッキ機能実装時）

## 4.2 認証必須

- ダッシュボード
- デッキ、単語、学習、統計、設定、履歴
- 同期API
- メタデータ更新API
- 音声取得API（公開データを除く）

## 4.3 所有者チェック

- User所有のリソースは、セッションの`userId`とリソースの`userId`が一致する場合のみ操作を許可する。
- Deck経由のWord、Card、FSRSState、ReviewLogも最終的にUser所有を検証する。
- 所有者でないリソースは、存在の有無を推測できないよう`NOT_FOUND`として扱う。

# 5. APIエラー

| 状況 | HTTP | code |
| --- | ---: | --- |
| セッションなし | 401 | `UNAUTHENTICATED` |
| セッション期限切れ・不正 | 401 | `INVALID_SESSION` |
| 所有権なし | 404 | `NOT_FOUND` |
| OAuth認証拒否 | 401 | `AUTHENTICATION_FAILED` |
| OAuth設定不備 | 500 | `AUTH_CONFIGURATION_ERROR` |

既存の共通APIレスポンス形式（`success`、`data`、`error`）を使用する。

# 6. 認証状態

```text
Unauthenticated
  └─ Google OAuth開始
       ├─ AuthenticationFailed
       └─ Authenticated
            └─ SessionExpired → Unauthenticated
```

# 7. 保留事項

- Google以外のOAuthプロバイダー追加
- 複数Googleアカウントの連携
- アカウント統合・メールアドレス変更処理
- 管理者ロール
- セッションの強制全失効UI

# 8. 既存設計との整合

- 要件定義書のGoogleログイン、外部認証、パスワード非保存に一致する。
- 基本設計書のAuth.js、セッション認証、Google認証に一致する。
- 詳細設計書およびPrisma Schemaの`passwordHash`は、本書確定後のMigrationで削除する。

# 9. 実装状況

- `src/auth.ts` にGoogle Provider、JWTセッション、User同期処理を実装した。
- `src/app/api/auth/[...nextauth]/route.ts` にAuth.jsの認証Handlerを接続した。
- `src/lib/require-auth.ts` に保護API向けの共通認証チェックを追加した。
- `prisma/migrations/20260724010000_google_oauth_authentication` に認証情報のMigrationを追加した。
- Google OAuthのcallback URLは、開発環境では `http://localhost:3000/api/auth/callback/google` とする。
